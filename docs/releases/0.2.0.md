# Release record: v0.2.0

**Date:** 2026-07-25
**Scope:** persona layer + coworking layer
**Previous:** 0.1.1

Everything unreleased since 0.1.1 ships together. Both subsystems answer the
same question from different directions: when an AI agent works on your behalf,
how do you know what it actually did? The coworking layer answers it for
humans, with a document you can watch. The persona layer answers it for
machines, with an append-only ledger of what was decided and why.

## Three packaging bugs found during the release

None were visible from the source tree. All three were found by building a
wheel and installing it somewhere clean, which is the only way they surface.

1. **Subpackages were never declared.** `pyproject.toml` listed only the
   top-level `novasystem` package, so `persona` and `coworking` were both
   absent from a built wheel entirely.
2. **Runtime assets were not declared.** The work log template and the agent
   hook are needed at runtime. Without `package-data` they are missing from a
   wheel and `coworking init`, the first command a new user runs, fails.
3. **The CLI imported Docker at module load.** `novasystem/cli.py` imported
   `Nova` eagerly, pulling in `docker` and `git`. The coworking commands need
   neither, so the CLI could not start on a machine without Docker installed.

## Still open

**This release is committed and pushed to `nova-persona-genesis`. It is not
tagged and not merged to `main`.**

The repository has no tags at all, so v0.2.0 is effectively its first tagged
release, which argues for tagging `main` rather than a feature branch.

```bash
# Option A: merge to main, tag there
git checkout main
git merge --no-ff nova-persona-genesis
git push origin main
git tag -a v0.2.0 -m "NovaSystem 0.2.0: coworking layer and persona layer"
git push origin v0.2.0
gh release create v0.2.0 --title "v0.2.0 - The Coworking Layer" --notes-file CHANGELOG.md

# Option B: publish to PyPI as well
python3 -m build
python3 -m twine upload dist/*
```
